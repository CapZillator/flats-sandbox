# SEO-аудит Manden — 16 октября 2026

Основной домен: `https://manden.me`. Проверены исходный код, реализация SEO в
`roama-web`, документация установленного Next.js 16.3.5, публичный контракт
`flats-back` и HTML локального приложения с реальными данными API. Production
домен, Search Console, поисковый индекс и Core Web Vitals этим аудитом не проверены.

Open Graph — метаданные для ссылочных превью. JSON-LD отдельно описывает смысл
объявления для поисковых систем; эти механизмы дополняют друг друга.

## Устройство JSON-LD

- `RealEstateListing` описывает страницу объявления, её язык, публикацию и обновление.
- `mainEntity` и `Offer.itemOffered` ссылаются на один объект недвижимости через `@id`.
- Квартира/студия имеет тип `Apartment`, дом/вилла — `House`. Дополнительный тип
  `Product` позволяет использовать объект как предмет `Offer`, как в подходе
  Schema.org к предложениям размещения.
- `UnitPriceSpecification` описывает исходную месячную цену и валюту объявления,
  `referenceQuantity` — один месяц (`MON`). Валюта JSON-LD не зависит от cookie
  посетителя и конвертации суммы для интерфейса.
- Адрес и координаты находятся у объекта недвижимости, а не у WebPage.
  Для локаций уровня района/квартала не придумывается название города.
- Площадь (`MTK`), спальни, ванные, этаж, разрешение животных, минимальный срок
  аренды и удобства берутся из публичных данных, отображаемых на странице.
- Невалидные координаты и отсутствующие необязательные поля пропускаются.
  Нулевой этаж и `petsAllowed: false` сохраняются.
- Наличие публикации не считается гарантией свободных дат: поле availability
  не генерируется. Контакты, закрытые авторизацией, в разметку не попадают.
- Символ `<` экранируется перед вставкой JSON-LD в HTML, чтобы пользовательское
  описание не могло закрыть script-тег.

Использован [RealEstateListing](https://schema.org/RealEstateListing) и модель
[Accommodation](https://schema.org/Accommodation), а не VacationRental: продукт
предназначен для среднесрочной и долгосрочной аренды. Разметка не гарантирует
расширенного сниппета. Для Google Vacation Rentals существуют отдельные условия
интеграции с Hotel Center и требования к партнёрам:
[документация Google](https://developers.google.com/search/docs/appearance/structured-data/vacation-rental).

## Что уже было хорошо

- Заголовок H1, описание, адрес, характеристики и месячная цена рендерятся сервером.
- Ссылки карточек ведут на публичные локализованные URL.
- `html lang` соответствует локали маршрута.
- Галерея использует next/image, responsive sizes и alt с fallback на заголовок.
- Backend выдаёт через публичные endpoints только опубликованные объекты.
- Английские URL не содержат `/en`; генерация SEO URL сохраняет эту схему.

## Проверки

На объявлении `mock-20261014-da-nang-studio` локальный HTML для Googlebot
содержал один JSON-LD script, правильные английские и русские canonical,
все три языковых альтернативы и заполненные Open Graph / Twitter Cards.
Sitemap успешно отдал 95 URL при 31 опубликованном объявлении: некоторые
языковые версии исключены из-за отсутствующего перевода. В robots.txt указан
`https://manden.me/sitemap.xml`.

Страница несуществующего объекта не содержит JSON-LD и получает `noindex`.
В текущем streaming-рендеринге её HTTP-статус — 200; это документированное
[поведение Next.js](https://nextjs.org/docs/app/api-reference/file-conventions/not-found).
Если потребуется именно HTTP 404 до начала streaming, понадобится отдельно
изменить границы загрузки/проверки существования объекта. Это не изменялось.

Добавлены проверки пагинации sitemap, отказа API без публикации неполной карты,
языковых альтернатив, fallback-переводов, месячной цены, отсутствующих данных,
нулевых значений и защиты JSON-LD от закрытия script-тега.

Итог: 54 тестовых файла, 209 тестов — успешно; `npm run format:check` — успешно.
Production-сборка через `npm run build -- --webpack` — успешно. Обычная сборка
Turbopack сначала прошла, но при повторном запуске завершилась внутренней ошибкой
открытия служебного порта (`Operation not permitted`), в том числе после запуска
вне sandbox. Конфигурация bundler проекта не менялась.

При проверке production-сборки также исправлен существующий пропуск
`propertyType` в `ListingCardData`: компонент карточки уже использовал это поле.

## После публикации

1. Установить `SITE_URL=https://manden.me` в production. Для локальной разработки
   использовать `http://localhost:3001`, как в `.env.example`.
2. Проверить HTTPS и единый origin: www/HTTP должны перенаправляться на основной
   домен. Проверить, что хостинг не добавляет production-страницам `noindex`.
   Закрыть staging от индексации на уровне окружения/хостинга.
3. Удалить тестовые объявления из production до открытия индексации. В локальной
   базе сейчас есть опубликованные объявления с `mock` в slug и тестовым текстом.
4. Подключить Search Console, отправить sitemap и проверить несколько объектов
   через URL Inspection. Проверить JSON-LD опубликованного HTML через
   [Schema Markup Validator](https://validator.schema.org/).
5. Замерить мобильные LCP, INP и CLS на production. Серверный shell ждёт session
   и exchange rates, страница объекта — availability; влияние задержек API на
   TTFB требует отдельного замера. У галереи первая фотография eager, но её
   фактический LCP и необходимость preload пока не измерены.
6. Добавлять индексируемые посадочные страницы городов и типов жилья отдельно
   от фильтров каталога, с уникальным содержимым. Сейчас параметризованный поиск
   намеренно закрыт от индексации, включая пагинацию; объекты доступны через sitemap.
7. При росте каталога разделить sitemap и добавить компактный backend SEO-feed.
   Текущая реализация читает публичный API страницами по 100, без пользовательских
   cookie; свыше 50 000 URL она явно завершится ошибкой вместо невалидной карты.
8. Подготовить общий OG-баннер для главной/каталога и проверить качество alt у
   фотографий: часть текущих alt похожа на имена файлов, а не описания изображений.

Robots.txt разрешает обход страниц с noindex, чтобы робот мог прочитать этот
метатег. Авторизация остаётся механизмом защиты приватных данных; robots.txt
и noindex не заменяют её.
